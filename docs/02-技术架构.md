# 02 · 技术架构

> 技术栈：Next.js（App Router）· TypeScript 全栈 · PostgreSQL + Drizzle ORM · Tailwind + shadcn/ui · TanStack Query + Zustand · pnpm Monorepo · Vercel 部署

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│ apps/web（Next.js，玩家端 + admin 路由）                  │
│  React Server Components / Client Components             │
│  TanStack Query ←→ API Routes                            │
└───────────────┬─────────────────────────────────────────┘
                │ /api/*（Route Handlers，zod 校验）
┌───────────────▼─────────────────────────────────────────┐
│ 服务端游戏服务层（server/services）                      │
│  TurnService（回合管线） CharacterService ArchiveService │
│  MarketService AdminService …                           │
├──────────────┬──────────────────────┬───────────────────┤
│ packages/    │ packages/            │ llm/（服务端模块） │
│  engine      │  content             │  provider 抽象     │
│  规则引擎    │  静态内容与剧本配置  │  prompt 组装        │
│  纯函数      │  zod schema          │  结构化输出解析     │
├──────────────┴──────────────────────┴───────────────────┤
│ PostgreSQL（Drizzle ORM）                                │
│  存档/世界状态/历史/静态数值表/运营埋点                    │
└─────────────────────────────────────────────────────────┘
```

核心原则：

1. **服务端权威**：游戏状态只存在于服务端 DB；客户端只做展示与输入。判定、演化、结算全部在服务端。
2. **先算后写**：LLM 只做叙事表达，不做任何数值决策。
3. **引擎纯函数化**：`packages/engine` 不依赖 IO，给定 `(state, action, seed)` 返回确定结果，可单测、可回放。

## 2. Monorepo 结构

```
XunXianOnline/
├─ apps/
│  └─ web/                    # Next.js 应用（含 /admin 管理后台路由组）
│     ├─ app/(game)/          # 玩家端页面
│     ├─ app/admin/           # 管理后台（中间件保护）
│     ├─ app/api/             # Route Handlers
│     └─ server/services/     # 游戏服务层（编排 engine + llm + db）
├─ packages/
│  ├─ engine/                 # 规则引擎（纯函数，0 依赖 IO）
│  │  ├─ combat/  growth/  world/  events/  rng/
│  ├─ shared/                 # 全栈共享类型 + zod schema（API 契约、游戏状态类型）
│  ├─ content/                # 静态内容包：种族/灵根/域/物品/功法基表 + 主线剧本 JSON
│  └─ ui/                     # （可选）跨端共享组件
├─ docs/                      # 本文档体系
└─ pnpm-workspace.yaml
```

`packages/content` 内置种子数据（开发期与初始化用），生产通过管理后台维护 DB 中的数值表（决策：静态数据入库+后台管理）；引擎读取 DB 快照，content 包作为版本基线。

## 3. 回合处理管线（核心链路）

玩家点击"进入下月"或选择行动后，`TurnService` 执行：

```
[0] 前置校验（存档归属、回合状态机合法迁移）
[1] 意图归一（选择编号 → 罗盘选项定义；自由文本 → LLM 意图解析层）
[2] 引擎判定（engine，纯函数，seed = hash(saveId, turnNo)）
     行动结算：修炼/探索/战斗(骰子)/交易/社交…
     数值变更集 Δ（修为/道基/道韵/功法/物品/灵石/关系/势力/技艺）
[3] 世界演化（engine.world）
     当月 NPC 行动骰子、势力关系骰子、区域演化、事件链推进、
     因缘际会清单（5月末）、天机简报结构化动态列表、
     决策罗盘 15 选项生成 + 保鲜期衰减
[4] LLM 叙事（llm，先算后写，单次主调用）
     输入：结构化结果 + 分层记忆（状态快照/近期摘要/相关人物事件卡）+ 模块化设定注入
     输出：JSON{ narrative, briefing润色, dialogues, 简要选项描述 }（zod 校验）
     失败：重试 1 次 → 模板降级（引擎可生成的保底文本）
[5] 持久化（单事务）：状态 Δ + 本回合记录（含 LLM 文本、seed、变更日志）
[6] 响应：返回结算视图模型（前端渲染演出）
```

- **随机种子**：`(saveId, turnNo)` 派生 → 任何回合可确定性重放（回放工具与调试基础）。
- **事务边界**：[2][3][5] 的状态写入在一个 DB 事务；LLM 调用在事务外，成功后随事务落库。
- **幂等**：`turnNo` 乐观锁防止双击/重放重复推进。

### 3.1 Vercel 超时应对

- 常规回合在单次请求内完成（目标 P95 < 8s，LLM 流式）。
- S 级演出回合（渡劫/终章等多段 LLM 调用）拆为：`POST /turn/start`（同步引擎结算并落库，返回 turnRecordId）+ `GET /turn/:id/narrative`（SSE 流式叙事）——引擎结果先行落库，LLM 文本异步补齐，刷新不丢失。

## 4. LLM 供应商抽象（详见 05 号文档）

- `LlmProvider` 接口统一 OpenAI 兼容协议；供应商/模型/参数存 DB 配置表，后台可切换与灰度（决策：完全可配，默认智谱 GLM 旗舰）。
- 服务端代理统一鉴权、限流、成本计量（每次调用记录 token 数与估算成本 → 成本看板）。

## 5. 防 SL 与安全

- 不可回滚：状态只追加（turn_records 单向链），无"读档"API；历史回看为只读视图。
- 输入校验：所有 API zod 校验；自由文本长度限制 + 内容安全过滤。
- 存档归属：设备 ID（httpOnly cookie）绑定存档；道果码恢复 = 码→存档重绑定（原设备解绑）。
- 限流：每设备回合频率、LLM 调用频率限流（Upstash Redis 或 DB 计数）。

## 6. 错误处理与降级链路

| 故障点 | 策略 |
|--------|------|
| LLM 超时/异常 | 重试 1 次 → 模板降级文本（引擎数据拼装，保证回合完整） |
| LLM 输出不符 schema | zod fail → 带错误信息重试 → 降级 |
| 意图解析失败 | 返回澄清追问（1 次），再失败给出就近的罗盘建议 |
| DB 事务失败 | 回滚，回合不推进，前端提示重试 |
| 世界演化计算异常 | 捕获并记录，当月演化跳过（标记 degraded，不阻塞回合） |

## 7. 关键非功能需求

- **性能**：月回合端到端（不含 LLM）< 500ms；NPC 演化批量计算（活跃 NPC ≤ 200/存档）。
- **可观测**：结构化日志（saveId/turnNo 贯穿）、LLM 调用全量记录（prompt 版本、token、耗时、结果校验状态）、运营埋点（见 09 号文档）。
- **测试**：engine 单测覆盖率 ≥ 90%（公式全量用例表）；回合管线集成测试（固定 seed 快照）；LLM 层 contract 测试（mock provider）。
