# 04 · 规则引擎设计（packages/engine）

> 全部纯函数、零 IO、确定性（显式传入 RNG）。所有公式与表格逐条对应 V8.1.3 设定原文。

---

## 1. 模块划分

```
packages/engine/
├─ rng/          # 种子随机：mulberry32/PCG，rng = createRng(hash(saveId, turnNo))
├─ character/    # 建角校验、属性派生（战力、寿元、修炼速度修正）
├─ growth/       # 修为/道基/道韵/功法/百艺经验曲线与升级
├─ breakthrough/ # 六大突破点与渡劫判定
├─ combat/       # 战斗性质分类、胜率、命运骰子、惩罚、掉落
├─ actions/      # 行动结算：修炼/探索/交易/社交/百艺/闭关…
├─ compass/      # 决策罗盘 15 选项生成与保鲜期
├─ world/        # NPC 演化、势力骰子、区域演化、物价、事件三层
├─ events/       # 事件链状态机执行器
├─ memory/       # 分层记忆筛选（供 LLM 注入的相关性打分）
└─ pipeline/     # 回合管线编排（纯函数版，服务层调用）
```

每个模块导出 `(state, input, rng, refs) → {delta, log}` 形态的函数；`refs` 为静态数值表快照。**engine 不写库、不调 LLM。**

## 2. 确定性与回放

- `seed = fnv1a(saveId ^ turnNo)`；同 seed 同输入必得同结果 → 回放工具直接复现任意回合。
- 回放工具（开发/客服用）：输入道果码+回合号 → 重放管线 → 对比落库 delta，定位数值问题。
- 所有概率判定必须经由 rng 实例，禁止 `Math.random()`（ESLint 规则强制）。

## 3. 各模块规格

### 3.1 character
- 建角：种族/年龄/灵根/出生地/开局包/道韵的加成叠算 → 初始 `player_state`；灵根按开局包保底规则随机。
- 派生公式：
  - `修炼速度修正 = 种族 × 灵根 × 洞府 ×(1+特殊体质) × 状态修正`
  - `战力 = 修为等级 + 主装备等级 + 主修功法等级`（设定三章二）
  - `外显战力 = 公开修为 + 公开装备`；敛息术/隐藏法宝降低外显。
  - 蓄力槽：外显 < 真实×阈值时每月 `+真实×0.1`（上限 真实×2）；释放后当月敌方判定 -10%~-30%（按蓄力比例）。
  - 战力评级映射（凡尘→飞升 7 档区间表）。

### 3.2 growth
- 境界经验表（50/150/350/650/1000/1800/3000 per 级，境界内递推）。
- 道基五维经验曲线：段位×每级需求（80/200/400/700/1200/2000）；经验获取事件映射（研读功法→悟性…）。
- 道韵升级条件与"道韵>道基×2 瓶颈期"判定（经验减半）与跨维修行破局。
- 功法：品级上限（凡30/灵50/地70/天90/仙100）、每级战力加成（0.8/1.0/1.2/1.5/2.0）、切换主修规则、遗忘/重修。
- 百艺：20 级晋升突破事件门槛、收入公式 `等级×系数+当月产出质量+市场需求`、主辅修 50% 规则。

### 3.3 breakthrough
六突破点状态机：条件校验（修为满溢+道具+契机）→ 劫类型（小天雷/心魔/四九/六九+天魔/九九+法则拷问/飞升劫）→ 骰子成败（道韵修正）→ 奖惩执行（寿元翻倍/倒退级数/丹碎/轮回触发）。输出 `BreakthroughResult`（S 级演出事件）。

### 3.4 combat
```
resolveCombat(state, foe, nature, rng, refs):
 1. nature ∈ {切磋, 生死仇杀, 妖兽, 自卫} → 收益/惩罚表选择
 2. 修为差 ≤5 且生死仇杀：战力高者直接胜；相等 → 策略博弈分
    （策略分 = 道韵相关项 + 战斗经验 + 环境因子，归一掷骰）
 3. 越级：base = 20% + (playerPower - foePower) × 1%
    dice = rollFateDice(rng, 修正项)   # 7 档概率表（8/12/20/20/20/12/8 %）
    final = clamp(base + dice.mod, 5%, 95%)
    隐性反馈档位 = byRange(final)  # 7 档氛围文案，不泄露数值
 4. 成败 → 惩罚/收益执行器：
    惩罚档位 = byPowerGap(战力差距%)  # 力竭/重伤/碾压/元婴灭/自爆
    天命战斗：惩罚减半+死亡庇护+功法保护；减免项（磐石之志/五行亲和/替死法宝/靠山）逐条扣减
    掉落表：主装备 60%（偷袭秒杀 80%）、功法 40%、储物袋 100%、特殊物 10%；
    金丹自爆掉率衰减；天人感应 +5%；正道击杀 → 追缉 flag
 5. 输出 CombatResult（供 A 级演出与结算面板）
```
命运骰子概率修正：天人感应（天赐+2/鸿运+2/天意-2）、未卜先知（天意-2/时运-2）、气运≥60/80（天赐+1/+1）、连续越级（负面微增，累计系数）。

### 3.5 actions
行动类型注册表：`cultivate / explore / trade / bargain / social / craft / seclude / travel / custom(意图解析产物)`。每个 action 定义输入 schema、结算函数、产物 delta。custom 行动由意图解析层产出 `{actionType, params}`，未匹配类型走 `freeform` 结算（保守数值 + LLM 叙事主导，事后回写有限 delta）。

### 3.6 compass
每月生成：六类配额采样（命途 2-3 / 因缘 2-3 / 历练 2-3 / 经营 2-3 / 百艺 1-2 / 闭关 1-2 = 15）。数据源：主线阶段选项（1-3 月）、pending_tasks 衍生、地舆图与简报、关系网、百艺状态。保鲜期 1-4 月，过期执行"自然发展"钩子。连续 3 回合无天命/因缘选择 → Lv.1 引导停发标记。

### 3.7 world（每月演化，回合驱动）
- NPC 批量演化：活跃 NPC（≤200）逐个掷行动骰（修炼/突破尝试/机缘/结仇/陨落/针对玩家敌对扫描）；轻量层（统计口径）只更新聚合数。
- 势力骰子：关系迁移（盟好↔反目等，tension 驱动）、吞并/分裂判定（中变层）。
- 区域演化：六维判定（市价波动/天象/修士流动/势力消长/道缘网络/天降机缘）→ event_log（表闻/中变/底流分层）。
- 5 月末：生成 6-7 月因缘际会清单（六类事件按条件+权重采样）。
- 天机简报：结构化条目列表（域动态/势力/轶闻/行情）→ 交 LLM 润色。

### 3.8 events（事件链状态机执行器）
```
节点定义（ref_event_chains / 主线剧本共用此执行器）：
{ id, entry: 条件, prompt: 叙事素材指令, options: [{label, requires, effects, next}],
  judgments: [{kind, params}], expiry?, onExpire }
执行：载入实例 state → 校验入口条件 → 展开当步 → 结算选项 effects/judgment → 迁移 next。
```
秘境（坠魔谷/古修洞府/遗迹）：多步状态机（入口→分层探索→判定→奖励/危险→结算），层数与奖励表入 ref_event_chains。

### 3.9 memory（LLM 注入筛选）
打分函数：相关人物（本回合交互、任务链引用、宿敌）＋近期事件（近 3 月详情）＋关键节点（突破/终章等 S/A 级）＋当前任务链摘要。输出 `MemoryBundle`（见 05 号文档）。

## 4. 测试规格

- **公式单测**：胜率边界（5%/95% 钳制）、骰子概率分布（卡方检验 10 万样本）、惩罚表全档位、经验曲线全境界、蓄力上限、掉落概率区间。
- **表格快照**：静态表驱动的用例自动生成（每个 ref 行至少一测）。
- **管线集成**：脚本化"人机自走"（随机策略跑 600 回合）断言不变量：灵石不为负、境界单调约束（惩罚允许回退但受表约束）、寿元逻辑、NPC 池上限。
- **回放一致性**：固定 seed 重放 N 存档 M 回合，delta 逐字节一致。
