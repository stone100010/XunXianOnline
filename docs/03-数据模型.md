# 03 · 数据模型设计（Drizzle / PostgreSQL）

> 分四组：身份与存档、动态游戏状态、世界模拟、静态数值表、运营数据。所有 JSON 字段均配 zod schema（packages/shared）双端校验。

---

## 1. 身份与存档

### devices（设备）
| 列 | 类型 | 说明 |
|---|---|---|
| id | uuid pk | |
| created_at | timestamptz | |
| last_seen_at | timestamptz | |

预留账号：`users` 表（id/email/password_hash/created_at）+ `devices.user_id` 外键，首版不启用注册流程。

### archives（存档，= 一个"仙途"）
| 列 | 类型 | 说明 |
|---|---|---|
| id | uuid pk | |
| device_id | uuid → devices | 归属设备 |
| slot | int | 槽位 1-3（可扩） |
| dao_fruit_code | varchar(9) unique | 道果码 `XXXX-XXXX` |
| status | enum | active / ended_ascend / ended_inherit / ended_reincarnate |
| seed | bigint | 世界随机种子（重开时重生成） |
| created_at / updated_at | timestamptz | |

道果码规范：8 位，字符集 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（去 0/O/1/I/L），带校验位（格式 `XXXX-XXXX`，末位为校验字符）防误输。恢复 = 校验码 → 绑定新设备（原设备解绑该槽）。

## 2. 动态游戏状态

### player_states（玩家核心状态，1 存档 1 行，热点行）
| 列 | 类型 | 说明 |
|---|---|---|
| archive_id | uuid pk | |
| turn_no | int | 总月数（乐观锁版本号） |
| game_year / game_month | int | 天玄历 |
| name / gender / race / age | | 基础信息 |
| realm_level | int | 1-100 |
| cultivation | jsonb | `{exp, nextExp, lifespan, lifespanMax}` |
| dao_bases | jsonb | 五维 `{wuxin,daoxin,genku,qiyun,xuemail: {level, exp}}` |
| dao_rhyme | jsonb | `{key, level, exp}` |
| spirit_root | jsonb | 灵根（系别/品级/纯度/修正） |
| combat | jsonb | `{power, displayed, displayConceal, momentum:{value,cap}}` 战力/外显/蓄力 |
| currencies | jsonb | `{low, mid, high, supreme, crystal}` 灵石五级 |
| skill_arts | jsonb | 百艺 `{main, subs[], levels}` |
| faction_status | jsonb | 势力身份递进状态 |
| location | jsonb | `{domain, region, place}` 三层位置 |
| tags | jsonb | 玩家行为标签（引导系统/事件触发用） |
| updated_at | timestamptz | |

### inventory_items（背包）
archive_id / item_ref_id（→静态表）/ meta jsonb（耐久、层数、绑定、本命标记）/ qty / acquired_turn。

### techniques_progress（功法修炼）
archive_id / technique_ref_id / level / exp / is_main（主修）/ is_destiny_protected（天命保护）。

### relations（道缘，玩家×NPC）
archive_id / npc_id / tier(0-4) / intimacy / interactions / shared_events / attitude jsonb（四维矩阵）/ last_contact_turn / decay_state。

### destiny_progress（天命主线）
archive_id / storyline_id(1-10) / stage(1-6) / phase enum（awaiting/locked/progressing/completed/waiting_years n）/ choices jsonb（每次抉择记录）/ rewards jsonb（已获增益）/ title（终章封号）。

### pending_tasks（未竟仙途/事件链实例）
archive_id / chain_id / chain_kind（destiny/karma/explore/…）/ state jsonb（状态机当前节点、变量、时限、保鲜期）/ expires_turn。

### compass_options（决策罗盘，每回合 15 项）
archive_id / turn_no / idx / kind（六类）/ label / payload jsonb（行动定义）/ risk_flag / freshness_expire_turn / is_selected / rendered_label（LLM 润色后文案）。

## 3. 世界模拟

### npcs（NPC 池，全局共享 + 存档实例态分离）
**全局池 `npc_pool`**：id / template_key / domain / faction_ref / profession / realm_range / traits jsonb / available（未被某存档深度占用）。
**存档实例 `npcs`**：archive_id / pool_npc_id / name / gender / race / age / realm_level / power / equipment jsonb / technique jsonb / goals jsonb / own_agenda jsonb（自身仙途进度）/ alive / spawned_turn。

> 池化策略（用户决策）：需要新 NPC 时先按（域/势力/行当/境界/性格）标签相似度匹配池中可用项；无匹配才 LLM 生成入池；单存档活跃 NPC 上限 200，全局池设上限并定期归并相似模板。

### factions（势力实例态）
archive_id / faction_ref_id / power / territory / relation_to_player（阶段一~四）/ internal jsonb（结构/底蕴/态度/氛围）。

### faction_relations（势力间关系）
archive_id / from / to / relation enum（盟好/敌对/依附/中立）/ tension float。

### world_state（天下总状态，1 存档 1 行）
archive_id / domains jsonb（7 域×五项种子属性+演化累计值）/ price_index jsonb（各域物价指数）/ undercurrents jsonb（底流事件积累）。

### turn_records（回合历史，只追加，防 SL 核心）
archive_id / turn_no pk / seed / phase enum（pipeline 阶段）/ engine_delta jsonb（数值变更集）/ narrative text（LLM 叙事）/ briefing jsonb / model_meta jsonb（模型/token/耗时/降级标记）/ created_at。

### event_log（世界事件日志）
archive_id / turn_no / layer（表闻/中变/底流）/ kind / payload jsonb —— 天机简报素材与历史回看。

## 5. 运营数据（详见 09 号文档）

- `analytics_events`：埋点宽表（device_id/archive_id/turn_no/event_kind/props jsonb/created_at）。
- `llm_calls`：每次 LLM 调用（provider/model/prompt_version/in_tokens/out_tokens/latency_ms/status/cost_est/archive_id/scene）。
- `admin_users` / `admin_settings`（含 LLM 供应商配置与灰度开关）。

## 6. 索引与规模策略

- 热点：`player_states.archive_id`；`turn_records(archive_id, turn_no)` 复合主键；`npcs(archive_id, alive)`；`relations(archive_id, npc_id)` 唯一。
- 历史归档：turn_records > 240（20 年）后 narrative 长文压缩为摘要行（`turn_summaries`），结构化 delta 保留；防膨胀。
- event_log 按月分区（首版可不做，预留）。
