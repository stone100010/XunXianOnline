# 06 · 天命主线剧本规范与事件链配置

> 决策：10 条主线 × 6 阶段**全量预写**为结构化 JSON（存 `ref_storylines` / `ref_event_chains`），引擎状态机执行，LLM 只做临场叙事。本文档定义配置 Schema 与生产流程。

---

## 1. 通用节点模型（主线与事件链共用执行器，见 04 号文档 §3.8）

```ts
ChainNode = {
  id: string,
  kind: "story" | "choice" | "judgment" | "battle" | "explore" | "reward" | "finale",
  entry: Condition[],            // 进入条件（全部满足）
  materials: {                   // 交给 LLM 的剧本素材（非生成文本）
    synopsis: string,            // 本节点剧情梗概（300 字内）
    keyNpcs: string[],           // 需要拉取/生成的 NPC 角色
    atmosphere: string           // 基调（悲壮/热血/诡谲…）
  },
  options: Option[],             // choice 节点：2-3 个互斥选项
  judgment?: JudgmentSpec,       // judgment/battle 节点判定参数
  effects: Effect[],             // 进入/完成时的效果
  next: string | DecisionFn,     // 下一节点或分支函数名
  expiryTurns?: number,          // 保鲜期（月），过期走 onExpire
  onExpire?: string              // 过期迁移节点（"错过天命静待来年"）
}

Option = {
  label, desc,
  requires?: Condition[],        // 门槛（修为/物品/关系/道韵）
  riskFlag?: bool,               // ⚠️风险标签（Lv.3 预警触发）
  effects: Effect[],
  judgment?: JudgmentSpec,       // 选项内判定（如斗法）
  next: string
}

Effect =                          // 由引擎统一执行的效果原语
  | { type: "exp", target: "cultivation|daoBase.x|daoRhyme|technique|art", value }
  | { type: "item", ref, qty }
  | { type: "currency", tier, qty }
  | { type: "relation", npc, intimacy, tier? }
  | { type: "flag", key, value }
  | { type: "unlock", what: "technique|skill|physique|artifact|law|domain|relic", ref }
  | { type: "spawnNpc", profile需求 }
  | { type: "move", location }
  | { type: "destinyReward", tier }   // 天命奖励体系（六章三节八类）

JudgmentSpec = { kind: "combat|luck|insight|social|will", params, fateDice?: bool }
Condition = { kind: "realm|item|relation|flag|turn|technique|age", op, value }
```

## 2. 主线剧本 Schema（ref_storylines.data）

```ts
Storyline = {
  key: "shengti" | "caifu" | "xuemail" | "nijing" | "zaizheng" | "hongchen"
      | "dandao" | "zongmen" | "zhujian" | "woming",     // ①~⑩
  name: string, bindPack: string,          // 绑定开局包
  tone: string,                            // 终章叙事基调与情感落点
  stages: Stage[6]
}
Stage = {
  index: 1..6,
  name: string,                            // 如"圣体初劫"
  realmGate: { min, max },                 // 修为达标触发（阶段锁定）
  rewardPreview: DestinyReward[],          // 阶段奖励（功法进阶/神通/体质/法宝胚/法则/领域/信物/封号）
  nodes: ChainNode[],                      // 本阶段节点图（含"待抉择"入口与错过分支）
  onStageComplete: Effect[]
}
```

规则实现要点（设定·第六章）：
- 1-3 月天命之召：stage.realmGate 满足且状态为 locked → 次年 1 月罗盘注入入口 choice 节点（2-3 互斥选项）。
- 错过：入口节点 expiry=3 个月，onExpire → 状态 awaiting（已等待 X 年累计），次年同期重新出现相同选项。
- 无视天命：主线状态机永不强制推进。
- 天命战斗保护：JudgmentSpec(kind=combat) 在主线节点上下文中自动启用惩罚减半/死亡庇护/功法保护（引擎 combat 模块按 flag 识别）。

## 4. 事件链与秘境配置（ref_event_chains）

- 因缘际会六类（宗门大比/秘境出世/兽潮/跨域冲突/轶闻/拍卖会）各配置 1-3 个模板链，年度采样实例化。
- **随机机缘**（首版重点）：坠魔谷、古修士洞府、上古遗迹等秘境模板：`入口(准入判定)→2-4 层探索(明察秋毫/未卜先知判定、遭遇表)→核心(机缘/守护者战斗)→离开(时限/反噬)`；奖励表挂 ref_items 高阶物品与功法。
- 跨年事件：链保留实例 state，次年 6-7 月刷新进展节点。

## 5. 终章与回顾

- 终幕节点 kind="finale"：终局抉择 2 选项 → 生成 FinaleReview（LLM 场景，输入全部抉择记录/奖励/道缘宿敌数据）→ 封号推荐 3 个 → 玩家自定义校验（2-8 字、唯一性、敏感词）→ 落库 `destiny_progress.title`，archive.status 置 ended。
- 回顾页五维数据全部来自 turn_records/destiny_progress/relations 聚合。

## 6. 生产流程与质量控制

1. 本 Schema 定稿 → 编写 `packages/content/storylines/*.json` 基线（60 阶段全量）。
2. 内容生产流水线：设定骨架（本文 §3）→ LLM 辅助起草节点素材（synopsis/atmosphere/选项文案）→ **人工校验**（判定平衡、奖励强度、与世界观一致）→ 入库。
3. 校验工具：加载时 zod 校验 + 图检查（节点可达、无死端、rewardPreview 与 effects 对应、realmGate 单调递增）。
4. 平衡红线：各主线同阶段奖励战力加成偏差 ≤ 15%（CI 用例强制）。
