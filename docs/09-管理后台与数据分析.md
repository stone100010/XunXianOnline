# 09 · 管理后台与数据分析

> 用户明确要求：**通过数据管理和分析游戏发展与规划，而不是蒙着头什么都不知道**。因此后台不只是数值 CRUD，而是"数值管理 + 运营分析 + 成本监控 + 客服工具"四位一体，与游戏首版同步交付。

---

## 1. 后台结构（/admin，管理员会话保护）

```
/admin                仪表盘总览
/admin/refs/*         静态数值表 CRUD（03 号文档 §4 全部表）
/admin/storylines     主线剧本可视化编辑（节点图 + 校验报告）
/admin/chains         事件链/秘境模板编辑
/admin/prompts        Prompt 版本管理与发布
/admin/llm            供应商/模型路由配置与灰度
/admin/players        玩家与存档检索 + 只读快照 + 回放工具
/admin/analytics/*    运营分析（§3）
/admin/audit          变更审计日志
```

## 2. 数值管理（refs CRUD）关键设计

- 每表专用表单（data 字段按 schema 渲染编辑器），而非裸 JSON 编辑；主键 key 不可改。
- **版本与快照**：修改生成新 `version` 草稿 → 发布生效；进行中存档锁定旧版本（03 号文档 §4），新存档用新版。
- **影响预览**：发布前 diff 报告（改动影响的境界/物品/主线范围）+ 仿真实跑（抽样存档离线重放 N 回合，输出数值漂移对比）。
- **审计**：所有变更记录 who/when/before/after。

## 3. 运营分析仪表盘（核心）

数据源：`analytics_events` 埋点 + `llm_calls` + 游戏库表聚合。指标分层：

### 3.1 用户与漏斗
- 设备→建角→完成首回合→第 12 回合（1 年）→第 36 回合（3 年）留存漏斗（按天/周 cohort）。
- 建角漏斗：7 步向导每步流失率（哪一步吓跑人：灵根？开局包？）。
- 会话：回合数/会话、会话时长、活跃设备 DAU/WAU。

### 3.2 游戏行为
- 境界分布（玩家群体卡在哪一级/哪次渡劫）。
- 突破成功率/渡劫失败率分布 → 数值平衡依据。
- 战斗统计：越级挑战频率、胜率实际分布 vs 理论（骰子公平性监控）、失败惩罚触发档位分布。
- 决策罗盘：各类型选项选择率、自由输入占比、澄清触发率（意图解析质量）。
- 主线进度分布：10 条主线的阶段到达率/等待年数分布/无视率（哪条主线不好玩）。
- 经济监控：灵石产出/消耗净流入曲线（通胀预警）、坊市交易热点物品、黑市使用率。
- 死亡/轮回/传承触发率与继承后留存（轮回机制是否真的"再续仙途"）。

### 3.3 LLM 成本与质量
- 成本：按天/场景/模型 的 token 与费用曲线；单存档月均成本；成本 TOP 存档。
- 质量：降级率（zod 失败/超时→模板兜底占比）、重试率、P95 延迟、叙事抽检评分队列。
- Prompt 版本对比：版本间成本/降级率/时长/人工评分。

### 3.4 世界健康度（独有视角）
- NPC 池：规模、命中率（复用 vs 新生成比例）、相似度匹配失败率。
- 事件链：各链触发率、完成率、中途放弃节点分布。
- 天机简报选项回应率（多少玩家真的看简报）。

## 4. 埋点设计（analytics_events）

统一事件模型 `{event_kind, props}`，关键事件清单：

| kind | props |
|---|---|
| create_step | step, choice（建角漏斗） |
| turn_action | optionKind, isFreeform, riskFlag |
| combat | nature, gapTier, diceFace, result, punishTier |
| breakthrough | point, result |
| market_trade | market, itemId, action |
| destiny_stage | storyline, stage, action(推进/无视/等待) |
| finale | storyline, choice, titleLen |
| reincarnate_inherit | mode |
| session | duration, turns |

含设备/存档/回合维度列；隐私：不采集任何个人信息，仅游戏行为。

## 5. 客服与运维工具

- 存档检索（道果码/设备）→ 只读状态快照（客服不得改档；如需修复走"补偿码"机制预留）。
- 回放工具 UI：道果码+回合号 → 重放对比（定位"我这回合为什么掉 5 级"类客诉）。
- 降级/异常告警通道预留（Slack/Webhook，Vercel cron 每日汇总）。

## 6. 实现要点

- 仪表盘聚合查询走只读副本/物化视图（PG matview 按天聚合，夜间刷新 + 实时小表直查），避免拖垮业务库。
- 图表 Recharts；后台页面 SSR + 客户端图表组件。
- 权限：首版单管理员角色，预留角色分级。
